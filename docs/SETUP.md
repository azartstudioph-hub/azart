# AZART: розгортання сайту крок за кроком

Сайт складається з трьох частин. Усі вони безкоштовні для вашого обсягу, і жодна не залежить від конструктора.

| Частина | Де живе | Що робить |
|---|---|---|
| **Сайт** (папка проєкту) | GitHub Pages | Сторінки, які бачать батьки й ви |
| **Сервер** (папка `backend/`) | Google Apps Script + Google Таблиця | Зберігає бланки, замовлення, ціни; рахує суми; перевіряє пароль адміністратора |
| **Фото** | Google Диск | Папки з фото, як і раніше; сайт читає їх напряму з браузера |

```
Браузер ──► GitHub Pages (HTML, CSS, JS)
   │
   ├──► Google Apps Script (/exec) ──► Google Таблиця   (бланки, замовлення, ціни)
   └──► Google Drive API (з ключем)  ──► папки з фото
```

Орієнтовний час: **40–60 хвилин** для першого запуску. Роблячи кроки, не пропускайте перевірки «Має вийти так»: вони швидко показують, де саме щось пішло не так.

---

## 1. Що потрібно мати

- Google-акаунт, на якому лежать фото (там же буде таблиця й сервер).
- Акаунт на [github.com](https://github.com) (безкоштовний).
- Комп'ютер із браузером. Для одноразового імпорту з Wix знадобляться ще CSV-файли з Wix.

Встановлювати програми не потрібно.

## 2. Сервер: Google Таблиця + Apps Script

### 2.1. Створіть таблицю

1. Відкрийте [sheets.google.com](https://sheets.google.com) → **Порожня таблиця**.
2. Назвіть її, наприклад, **AZART — база даних**. Аркуші створяться самі.

### 2.2. Вставте код сервера

1. У таблиці: **Розширення → Apps Script**. Відкриється редактор.
2. Файл `Код.gs` (або `Code.gs`), який там уже є, можна видалити або перейменувати.
3. Для кожного файлу з папки `backend/` проєкту створіть однойменний файл у редакторі (кнопка **+ → Скрипт**) і вставте вміст:
   `Config.gs`, `Db.gs`, `Pricing.gs`, `Api.gs`, `Admin.gs`, `Setup.gs`.
   Розширення `.gs` редактор додає сам, тому в назві пишіть `Config`, `Db` тощо.
4. Налаштування маніфесту: зліва **Параметри проєкту** (значок шестерні) → поставте галочку **Показувати файл маніфесту «appsscript.json» у редакторі**. Поверніться в редактор, відкрийте `appsscript.json` і замініть його вміст на вміст `backend/appsscript.json` (часовий пояс Київ, доступ до Таблиць, Диска й зовнішніх запитів).
5. Натисніть **Зберегти** (значок дискети).

### 2.3. Задайте пароль адміністратора

1. **Параметри проєкту → Властивості скрипта → Додати властивість скрипта**.
2. Назва: `ADMIN_PASSWORD`, значення: ваш пароль (довгий, не «1234»).
3. Збережіть властивості скрипта.

Якщо пропустити цей крок, `setup()` створить випадковий пароль і покаже його в журналі. Його можна змінити тут у будь-який момент. **Після зміни пароля всі раніше видані входи автоматично стають недійсними.**

### 2.4. Запустіть `setup()`

1. У редакторі зверху оберіть функцію **`setup`** і натисніть **Виконати**.
2. Google попросить дозволи. Натисніть **Переглянути дозволи** → оберіть свій акаунт → якщо з'явиться «Google не перевіряв цей застосунок», натисніть **Додатково → Перейти до … (небезпечно)** → **Дозволити**. Це ваш власний скрипт, тож усе гаразд.
3. Відкрийте журнал виконання (внизу). Має вийти приблизно так:
   ```
   Використовується таблиця, до якої прив'язано скрипт: AZART — база даних
   Аркуші: Albums, Orders, OrderItems, Prices, Settings, GroupPhotos
   Записано ціни за замовчуванням ...
   Пароль адміністратора вже задано.
   Папка для фото груп: https://drive.google.com/drive/folders/...
   Готово. Тепер: Deploy → New deployment → Web app ...
   ```
4. У таблиці з'являться шість аркушів. **Не змінюйте назви аркушів і перший рядок із заголовками.**

Для перевірки запустіть функцію **`selfTest`**: у журналі всі рядки мають починатися з `OK`.

### 2.5. Опублікуйте як веб-застосунок

1. **Розгорнути → Нове розгортання** (Deploy → New deployment).
2. Значок шестерні поруч із «Вибрати тип» → **Веб-застосунок**.
3. Заповніть:
   - **Опис:** `AZART API v1`
   - **Виконувати від імені:** **Я** (ваш акаунт)
   - **Хто має доступ:** **Усі** (Anyone)
4. **Розгорнути** → скопіюйте **URL веб-застосунку**. Він закінчується на `/exec`.

**Перевірка.** Відкрийте цей URL у браузері. Має з'явитись приблизно таке:

```json
{"ok":true,"data":{"service":"azart-api","version":"1.0.0","time":"2026-..."}}
```

> **Коли зміните код сервера пізніше:** **Розгорнути → Керувати розгортаннями → олівець → Версія: Нова версія → Розгорнути**. URL залишається тим самим. Якщо створити *нове* розгортання, URL зміниться і його доведеться оновити в `config.js`.

## 3. Ключ Google Drive API

Сайт читає списки папок і мініатюри фото з Диска напряму через Drive API. Для цього потрібен ключ (він безкоштовний).

1. Відкрийте [console.cloud.google.com](https://console.cloud.google.com) і створіть проєкт (наприклад, `azart`).
2. **API та сервіси → Бібліотека** → знайдіть **Google Drive API** → **Увімкнути**.
3. **API та сервіси → Облікові дані → Створити облікові дані → Ключ API**.
4. Одразу відкрийте створений ключ і **обмежте його**:
   - **Обмеження програм → Веб-сайти (HTTP-референти)** → додайте:
     - `https://ВАШ-ЛОГІН.github.io/*` (або адреса вашого домену, див. розділ 6);
     - для перевірки на своєму комп'ютері: `http://localhost:*`.
   - **Обмеження API → Обмежити ключ → Google Drive API**.
5. Збережіть. Зміни Google застосовує за кілька хвилин.

Ключ буде видно в коді сайту: так працюють усі браузерні ключі. Захищає його саме обмеження за адресою сайту та за API, тому пункт 4 обов'язковий.

> **Старий ключ із Wix** (якщо він колись потрапляв у чат, скріншоти чи код): видаліть його в тій самій консолі й створіть новий. Так само замініть старий службовий ключ сортувальника `sort_photo_azart` (його в новій версії вже немає) і ніколи нікому не надсилайте `private_key` зі службових акаунтів.

## 4. Папки з фото на Google Диску

Сайт бачить папку, яку відкрито **«Усім, хто має посилання → Читач»**. Окремий службовий акаунт, як у Wix, більше не потрібен.

Для кожного бланка:

```
Папка бланка                      ← її посилання/ID вказуєте в бланку
├── Група 1                       ← підпапки груп (назва = назва групи)
│    ├── IMG_0001.JPG
│    └── …
├── Група 2
└── …
```

Якщо груп немає, фото лежать просто в папці бланка, і сайт покаже їх однією галереєю.

1. Правою кнопкою на папці → **Надати доступ → Усі, хто має посилання → Читач**. Підпапки успадковують доступ.
2. У бланку (розділ 7) вставте посилання на папку: сайт сам витягне з нього ID.
3. Кнопка **«Перевірити папку»** у вікні бланка показує, скільки груп і фото знайдено. Якщо там помилка, причина майже завжди в доступі до папки або в обмеженнях ключа.

> Якщо ваш акаунт належить до робочого простору Google Workspace, адміністратор домену може забороняти доступ «за посиланням». Тоді потрібен звичайний особистий акаунт Google для папок із фото.

## 5. Налаштування сайту (`assets/js/config.js`)

Це єдиний файл, який треба відредагувати. Відкрийте його в будь-якому текстовому редакторі (або прямо на GitHub після завантаження: значок олівця).

```js
export const CONFIG = {
  API_URL: 'https://script.google.com/macros/s/…/exec',   // з кроку 2.5
  DRIVE_API_KEY: 'AIza…',                                  // з розділу 3
  KINDERGARTENS: ['Сад 1', 'Сад 7'],                       // назви садочків
  CONTACT: { phone: '+380…', phoneLabel: '…', viber: '…', telegram: 'https://t.me/ВАШ_НІК' },
  SCHEDULE: { uk: '…', en: '…' },                          // графік роботи у футері
  …
};
```

- `KINDERGARTENS`: список садочків. Додали садок: допишіть сюди назву, і він з'явиться на сторінці «Замовлення» та у виборі при створенні бланка. Уже створені бланки зберігають свою назву садка.
- `CONTACT.telegram`: у файлі стоїть посилання за номером телефону. Якщо у вас є нік, замініть на `https://t.me/ВАШ_НІК`.
- `DEFAULT_LANG`: `'uk'` або `'en'`.

## 6. Публікація на GitHub Pages

1. На github.com: **New repository** → назва, наприклад, `azart` → **Public** → **Create**.
2. Завантажте весь вміст папки проєкту: **Add file → Upload files**, перетягніть файли й папки (залишайте структуру), **Commit changes**. Або через `git`:
   ```bash
   git init && git add . && git commit -m "AZART"
   git branch -M main
   git remote add origin https://github.com/ВАШ-ЛОГІН/azart.git
   git push -u origin main
   ```
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save**.
4. Через 1–2 хвилини сайт з'явиться за адресою `https://ВАШ-ЛОГІН.github.io/azart/`.

**Перевірка.** Відкрийте адресу: має відкритись головна сторінка AZART з кроками замовлення. Усі посилання на сайті відносні, тому він працює однаково в підпапці `/azart/` і на власному домені.

**Власний домен** (за бажанням): у **Settings → Pages → Custom domain** вкажіть домен, у DNS додайте запис за інструкцією GitHub й увімкніть **Enforce HTTPS**. Потім додайте новий домен у HTTP-референти ключа Drive API (розділ 3).

**Не публікуйте** в репозиторії справжні дані клієнтів (експорти CSV із Wix). Репозиторій публічний. Імпорт відбувається в браузері, файли нікуди не потрапляють.

Папки `dev/`, `tests/`, `backend/`, `docs/` на роботу сайту не впливають. Їх можна залишити (код сервера не містить паролів: пароль лежить лише у властивостях скрипта) або не завантажувати.

Сторінки мають `noindex`: пошуковики їх не покажуть. Якщо потрібно, щоб головну знаходив Google, приберіть рядок `<meta name="robots" …>` у `index.html`.

## 7. Перший запуск: від входу до тестового замовлення

1. Відкрийте `…/admin.html` → введіть пароль. Посилання «Сторінка адміністратора» є зверху на головній сторінці, але зручніше додати адресу в закладки.
2. **Налаштування цін**: перевірте або змініть ціни (див. розділ 9). Кнопка «Зберегти» застосовує їх одразу.
3. **Параметри сайту**: оберіть, як показувати імена батькам (повністю чи скорочено) і чи приймати замовлення після кінцевої дати.
4. **Створити бланк**:
   - назва (унікальна), садочок, посилання на папку Google Диска (кнопка «Перевірити папку»);
   - типи фото (Репортаж, На фоні; «Портрет» не поєднується з іншими), розміри, формати;
   - кінцева дата прийому (включно з цим днем, за київським часом);
   - прапорець «Подарунок», якщо діє акція (безкоштовні електронні фото від порогової суми з налаштувань цін);
   - за потреби «Діапазони типів»: які номери фото вважати «На фоні», а які «Репортаж» (можна окремо для кожної групи).
5. Відкрийте бланк як клієнт (`orders.html` → ваш садок → бланк → група), оберіть фото, оформіть **тестове замовлення**.
6. Поверніться в адмінку → бланк → замовлення, перевірте суму, статус, друк. Тестове замовлення видаліть (кнопка «Видалити замовлення» на його сторінці).

## 8. Перенесення даних із Wix (одноразово)

Нічого з Wix не пропаде: старі замовлення, ціни й фото груп переносяться окремою сторінкою.

1. **Експорт із Wix.** У конструкторі відкрийте **Диспетчер вмісту (Content Manager)**, для кожної колекції: **… → Експорт → CSV**. Потрібні `AlbumSettings`, `Orders`, `OrderItems`, `PriceSettings`, `GroupPhotoLibrary`. Не обов'язково всі.
2. Увійдіть у `admin.html` і натисніть **«Імпорт із Wix»** (рядок під кнопками) або відкрийте `import.html`.
3. Перетягніть або виберіть CSV-файли. Сторінка сама визнає, що це за колекція, і покаже, скільки рядків прочитано.
4. **Бланки.** У Wix садочок для бланка не зберігався, тому для кожного бланка оберіть **садочок** (або оберіть для всіх і натисніть «Застосувати»). Прапорець **«Подарунок»**: у Wix він міг бути порожнім, тоді стоїть «вимкнено»: **перевірте його вручну** для кожного бланка, що мав акцію. Бланки з помилками (наприклад, без типів фото) імпортувати не можна: програма це покаже.
5. Перегляньте блок **«Перевірка файлів»**: замовлення без бланка чи позиції без замовлення пропускаються, про це буде написано. Зауваження про суми нормальне, якщо діяла знижка.
6. Залишіть галочки «Імпортувати ціни» (замінить поточні) та «Перенести фото груп на Google Диск» → **Імпортувати**.
7. Дочекайтесь «Імпорт завершено». Якщо перенесення фото не завершилось або частину фото не вдалось завантажити, натисніть **«Продовжити перенесення фото»**.

Особливості:

- **Імпорт безпечний при повторі.** Записи з тими самими ID оновлюються, а не дублюються. Якщо щось перервалось, просто запустіть імпорт ще раз.
- Старі замовлення **зберігають суми з Wix** без перерахунку.
- Експорт із Wix **не зберігає порядок рядків** у замовленні, тому після імпорту рядки впорядковані за номером фото.
- **Фото груп** спочатку записуються як посилання на сховище Wix, а потім копіюються у вашу папку «AZART — фото груп» на Google Диску (її створив `setup()`). **Не закривайте старий сайт Wix, доки перенесення не завершилось**: поки фото лежать на Wix, вони відкриваються лише завдяки йому.
- ID папок Google Диска, що лишились у старих бланках, перевірте у вікні бланка («Перевірити папку»). Деякі ID в експорті бувають неправильними (занадто короткими), і імпорт про це попередить.

Потім можна поступово вимикати Wix-сайт і видалити його службовий акаунт Drive API.

## 9. Ціни та знижки

Ціни редагуються в адмінці (**Налаштування цін**) і зберігаються в аркуші `Prices`. Суму замовлення завжди рахує сервер (браузеру довіряти не можна), тому клієнтам її не підкрутити.

- Друк за розміром і типом (На фоні / Репортаж / Портрет); електронні фото; доплата «друк + електронні».
- **Подарунок:** якщо бланк має прапорець акції й база замовлення досягла порога (`discountThreshold`), доплата за «друк + електронні» не береться.
- **Відсоткова знижка** за сумою (три порогові рівні, наприклад 1000 → 10%, 1500 → 15%, 2000 → 20%).
- **Портрет, «Вся фотосесія»:** фіксована ціна `portretSessionPrice`; галочка з'являється, лише якщо ціна більша за 0.

## 10. Щоденна робота

**Батьки:** `orders.html` → садок → бланк → група → вибір фото → форма → «Відправити». Після відправки вони бачать суму та кнопку «Перейти до перегляду замовлення». Адреса цієї сторінки містить секретний ключ (`order.html?id=…&key=…`): лише за нею видно телефон і коментар, тому батькам радять зберегти посилання.

**Ви:**

1. `admin.html` → «Ваші бланки»: кінцева дата, кількість замовлень.
2. **Відкрити** → група → список замовлень (імена, суми, статуси).
3. Замовлення → статус «Нове / В роботі / Готово» → «Зберегти»; **«Створити стрічку номерів»** копіює `IMG_1 OR IMG_2 OR …` для пошуку у Провіднику.
4. **Друкувати** (у списку замовлень бланка/групи): таблиця для друкарні, що вміщується на A4; можна вмикати й вимикати коментарі.
5. **«Створити директорію папок»** (на сторінці груп): [сортувальник](../sorter/index.html) створює на комп'ютері структуру папок для друку й електронної видачі. Працює в Chrome або Edge; вхід за тим самим паролем.
6. На картці групи кнопка **«завантажити»** додає фото групи для обкладинки.

## 11. Безпека та приватність

- **Пароль адміністратора** лежить лише у властивостях скрипта. Вхід видає підписаний токен на 12 годин (зберігається в браузері).
- **Захист від підбору пароля** глобальний: Apps Script не бачить IP-адрес, тому після 10 невдалих спроб за 10 хвилин вхід блокується для всіх приблизно на 10 хвилин (навіть для вас). Зачекайте й повторіть.
- **Телефон і коментар** в публічних списках сховані. Їх бачить адміністратор і власник посилання з ключем. Імена в публічному списку можна скоротити (параметр сайту).
- **Дані клієнтів** лежать у вашій Google Таблиці: надавайте до неї доступ лише тим, кому довіряєте.
- Ключ Drive API обмежений за адресою сайту (розділ 3).
- Сервер обмежує кількість запитів на створення замовлень (захист від спаму) і розмір запитів.

## 12. Якщо щось не працює

| Симптом | Що перевірити |
|---|---|
| На сайті: «Не налаштовано адресу сервера» | У `config.js` порожній `API_URL`: вставте URL із кроку 2.5 |
| «Помилка мережі», у консолі CORS | URL має закінчуватись на `/exec`; доступ розгортання: **Усі**; після змін коду потрібна **нова версія** розгортання |
| «Потрібен вхід адміністратора» після змін на сервері | Зайдіть знову: пароль змінювали або токен застарів |
| Фото не показуються, «Немає доступу до Google Диска» | Папка не відкрита «усім за посиланням»; ключ не має Drive API або HTTP-референт не збігається з адресою сайту |
| «Папка не знайдена» | Неправильний ID/посилання в бланку |
| Не вдається перенести фото груп із Wix | Старий сайт Wix уже вимкнено, або фото було видалено в Wix: завантажте фото груп вручну кнопкою «завантажити» |
| Забули пароль | Змініть `ADMIN_PASSWORD` у властивостях скрипта |
| Вхід «заблоковано» | Було забагато невдалих спроб: зачекайте 10 хвилин |
| «Скрипт перевищив ліміт часу» | Імпорт великих обсягів: повторіть імпорт (він продовжить, а не продублює) |

Ліміти Google (кількість запусків скрипта на добу, обсяг і час виконання) час від часу змінюються: поточні значення дивіться в документації Apps Script (Quotas). Для типового садочкового сезону їх з великим запасом вистачає.

## 13. Локальна перевірка та тести (для розробників)

Потрібен Node.js 20+.

```bash
npm run dev      # http://localhost:8080: сайт + емульований сервер, пароль admin
npm test         # усі тести (юніт + браузер Playwright)
```

`dev/` містить емулятор Apps Script і імітацію Drive API, тож сайт можна пробувати без Google. Для браузерних тестів потрібен встановлений Playwright (`npm i -g playwright`) із Chromium.
